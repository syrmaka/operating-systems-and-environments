## Содержание лекции

### Дерево каталогов и пути

Файлы Linux образуют одно дерево с вершиной в корневом каталоге `/`.
**Абсолютный путь** начинается с `/` и не зависит от текущего каталога, **относительный** отсчитывается от текущего. Личные файлы пользователя лежат в домашнем каталоге `~`; имена, начинающиеся с точки, скрыты.

### Стандарт FHS

**FHS** (Filesystem Hierarchy Standard) задаёт назначение основных каталогов. Файлы распределяются по типу данных:

| Каталог | Что хранит |
|---|---|
| `/etc` | настройки — текстовые конфигурационные файлы |
| `/usr` | программы из пакетов; установленные вручную — `/usr/local` |
| `/var` | изменяемые данные: `/var/lib` — постоянные, `/var/log` — журналы, `/var/cache` — кэш, `/var/spool` — очереди |
| `/tmp`, `/run` | временные данные, очищаются при перезагрузке; `/var/tmp` не очищается |
| `/dev` | файлы устройств: `c` — символьные, `b` — блочные |
| `/proc`, `/sys` | сведения ядра о процессах и устройствах; содержимое формируется при чтении |

В Ubuntu `/bin`, `/sbin` и `/lib` — ссылки на каталоги внутри `/usr`.
Учётные записи описаны в `/etc/passwd`, пароли хранятся в `/etc/shadow`.

### Как оболочка находит программу

Оболочка ищет исполняемый файл по каталогам из переменной `PATH` и запускает первый найденный. Встроенные команды, например `cd`, выполняет сама оболочка. Как разрешается имя, показывают `command -v` и `type`.

### Inode и ссылки

Сведения о файле (права, владелец, размер, расположение данных) хранятся в **inode**, имя файла — в каталоге. **Жёсткая ссылка** — ещё одно имя того же inode; данные удаляются вместе с последним именем. **Символическая ссылка** хранит путь и перестаёт работать, если по этому пути файла нет.

### Монтирование

Файловая система определяет способ хранения файлов: ext4, tmpfs (в оперативной памяти), proc, sysfs. **Монтирование** подключает файловую систему к каталогу — точке монтирования. `findmnt` показывает подключённые файловые системы, `lsblk` — диски и разделы, `df -h` — свободное место, `du -sh` — место, занятое каталогом.
